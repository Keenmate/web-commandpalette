# Building & testing

```bash
npm install
npm run dev              # examples hub + pages on http://localhost:12400
npm run build            # cem analyze → vite build (dist/) → check:vars:strict
npm run build:examples   # static examples site → dist-examples/
npm run preview:examples # serve it on http://localhost:12401
npx kmwc doctor          # devkit checks + the BlissFramework rulebook suites
npm run test:unit        # vitest (machine + helpers)
npm run test:e2e:install # once: Playwright chromium
npm run test:e2e         # Playwright (desktop + Pixel 7 projects)
npm run package          # build + npm pack
```

Ports, titles and the image name come from `package.json#kmwc`. The `Makefile`, `Dockerfile`,
`nginx.conf` and `.dockerignore` are generated by `npx kmwc sync` from
`@keenmate/web-components-devkit` — don't edit them; repo-specific targets go in `Makefile.local`.

The same tasks are available through `make` (run `make` to list them): `make dev`, `make build`,
`make test`, `make kill-port`, `make publish-dry`, `make publish-rc`
(the `rc` dist-tag; `latest` is untouched) and `make publish` (`latest`). The publish targets ask
for confirmation and always clean and rebuild `dist/` first. A pre-release version (`x.y.z-rcNN`)
must go out through `publish-rc`, because npm rejects it without a dist-tag.

Single tests: `npx vitest run test/unit/palette.test.ts`, `npx vitest run -t "context search"`,
`npx playwright test e2e/wizard.spec.ts`.

## Outputs

- `dist/web-commandpalette.js` (ESM), `dist/web-commandpalette.umd.js`, `dist/index.d.ts` —
  `@keenmate/web-components-core` is bundled; the palette CSS is inlined into the JS (shadow root).
- `custom-elements.json`, `web-types.json`, `vscode.html-custom-data.json`,
  `vscode.css-custom-data.json` — generated by `cem analyze` from the element's `static inputs` /
  `static events` tables and `component-variables.manifest.json`. Not committed.

## The CSS pipeline

`src/css/main.scss` `@use`s core's partials straight out of `node_modules/@keenmate/pure-admin-core`.
`scripts/shadow-css.mjs` compiles it with Sass (a Vite plugin — Vite's own Sass importer rejects the
bare `@import`s inside core because of package `exports`) and adapts the output to the shadow root:
fallback-less `var(--x)` reads get core's defaults as fallbacks, and `rem` becomes
`calc(N * var(--base-rem, 10px))`. The build fails if a `--pa-*` / `--pc-*` variable survives the
adapter. `npm run check:vars` (`kmwc check-vars`, `consumed` mode) validates the manifest against
the built bundle, so it runs after `vite build`.

To pick up a new core palette: bump `@keenmate/pure-admin-core`, rebuild, run `check:vars`.

## Examples site image

`make image-build` builds a two-stage image: a Node stage runs `npm run build:examples` (a Vite
multi-page build of every root `*.html`, with the version badge stamped at build time), and an
nginx stage serves `dist-examples/`. `make image-run` serves it on http://localhost:12410, and `make image-stop` / `make image-clean`
tear it down. The runner defaults to podman; set `DOCKER_RUNNER`, `IMAGE_NAME`, `CONTAINER_NAME`
or `IMAGE_PORT` in an uncommitted `.makefile.env`.
