CS01 · Static Steps

A step is static by default. Its options are either listed inline (options) or fetched once on step entry from getStepOptionsCallback with an empty term. After that, typing filters in the browser with no round-trips. /assign fetches products, then users, through the callback. /go uses inline options. 

{ id: 'go', trigger: '/go', text: 'Go to Page',
  steps: [{ id: 'page', options: [{ text: 'Users', value: '/users' }, …] }] }

CS02 · Live Steps (isLiveSearch: true)

Mark a step isLiveSearch: true only when its options can't be listed up front. getStepOptionsCallback({ commandId, stepId, term, selections, signal }) is then called on every keystroke, after the debounce. In /deploy, pick an environment and the branch step queries live.

CS03 · Free Text, Conditional & Branching Steps

isFreeTextAllowed: true means pressing Enter when nothing matches submits the typed text (try /go /my/custom/path). getIsVisibleCallback({ selections }) returning false skips a step: in /report, “Inventory Status” has no time range, so the command completes right away. An option with its own steps forks the wizard: /assign-admin John to group Finance vs … to site Intranet.

CS04 · Display & Stepping Back

With display="inline", the input keeps the sentence built so far (/deploy to Staging branch ) and locks everything before your answer. With display="tokens", earlier answers become removable badges above an empty input. Esc, or ⌫ at the start of your answer, goes back one step.

CS05 · Instant Commands & Hotkeys

Every command fires one action event (detail.id = the command id). A command without steps fires it at once with empty selections; a wizard fires it after the last answer, with selections ({ stepId, label, value, optionId?, isFreeText }). With the palette closed and focus outside any field, try g r (instant) or g d.
