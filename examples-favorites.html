FR01 · Reusable Pickers (step.getOptionsCallback)

Each picker is defined once and spread into any step that needs it. A step's own getOptionsCallback wins over getStepOptionsCallback, so there's no switch (commandId + stepId). pickUser is a live (isLiveSearch: true) lookup; pickGroup / pickSite load once and filter in the browser; the permission list is fixed inline. 

const pickUser  = { isLiveSearch: true, placeholder: 'User…',  getOptionsCallback: ({ term, signal }) => api.users(term, signal) };
const pickGroup = {               placeholder: 'Group…', getOptionsCallback: ({ signal }) => api.groups(signal) };

FR02 · Favorites & Recent

Run a few commands, then reopen the palette: the home screen starts with Recent, ranked by how often and how recently you used each item. Commands, completed runs, contexts and search results are all remembered. Star the active row with Ctrl/⌘+D or the ☆ button to pin it under Favorites. The home screen keeps both sections short (max-favorite-count / max-recent-count, 3 by default). The full lists are one chord away: Ctrl/⌘+F for favorites and Ctrl/⌘+R for recent (type to filter). Or click the section heading's “+N” control. With the palette closed, g f opens it straight on favorites. By default everything lives in localStorage under usage-key; switch the user to see that each key keeps its own list.

FR03 · Replaying a Run

Run /add-permission write to Peter Parker, then reopen the palette and pick it from Recent. The wizard reopens with each remembered answer offered first:

  • Enter runs the rest of the remembered answers. Choosing it from Recent and pressing Enter again repeats the whole command.
  • Tab accepts the current step and moves to the next one, so you can walk through the run step by step.
  • Typing replaces the current step's answer (“…write to Ja” → Jane). Enter then keeps the answers after it.
  • Shift+Tab, Esc or ⌫ at the start step back.

Branches replay too: /assign-admin … to site Intranet comes back as a site run. If a branching step's list is still loading, Enter stops there; press it again once the list appears.

FR05 · Grouped Results & Context searchCallback

Results with a group appear under headings, grouped in the order each group first appears. Global search for “an” returns users, groups and sites. The :users context brings its own searchCallback, so the element's searchCallback is never asked for it.

FR06 · Feedback

When a command finishes, the dialog briefly collapses to one line showing what ran (✓ /deploy to Staging branch main · Done) instead of vanishing the moment you press Enter. The action event still fires immediately; only the closing waits. Any key or click dismisses it, and Ctrl/⌘+K goes straight to a fresh palette. renderFeedbackCallback(ctx) can replace the content, return false to skip the feedback, or opt search-result selections in. By default they get none, because they usually navigate away.

palette.renderFeedbackCallback = (ctx) => {
    if (ctx.type === 'select') return `Opening <b>${ctx.sentence}</b>…`;
    if (ctx.commandId === 'reload') return false;             // no confirmation for this one
    return `<b>${ctx.commandText}</b> queued — ${ctx.selections.map((s) => s.label).join(' → ')}`;
};
