# Web CommandPalette 1.0.0-rc03 — Release Notes

**Released:** 2026-11-22 · **Pre-release** (`npm install @keenmate/web-commandpalette@rc`)

These notes cover the changes since **1.0.0-rc02**, the last version on npm (published 2026-10-12).
They are the first release notes for this package; for earlier versions read the
[CHANGELOG](https://github.com/Keenmate/web-commandpalette/blob/prod/CHANGELOG.md). 1.0.0-rc01 never
reached npm; its content shipped in rc02.

This rc moves the palette onto the shared Keenmate interaction model and the rest of
`@keenmate/web-components-core` rc25: events lose their `cp-` prefix and a command run is one
`action` event, commands are core action items, every callback takes one `ctx`, and `el.controller`
is the public facade. The palette's own CSS now sits on the `@keenmate/base-css-variables` 2.0
contract, and it is a core modal (inert page, phone Back, modal stacking tier). Search, labels,
icons, keyboard shortcuts, announcements and persisted favorites / recents go through core's shared
modules, and the engine is public for building your own UI (`CommandPaletteEngine`). It is
**breaking, with no aliases.** Note that a `^1.0.0-rc02` range **does** pull this rc (npm matches
later prereleases of the same `1.0.0`), so pin the version until the checklist below is done.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/Keenmate/web-commandpalette/blob/prod/CHANGELOG.md) (section
1.0.0-rc03); this document is the upgrade guide and the highlights.

## Breaking changes

### Renamed attributes and properties

The v1 naming pass gave every Keenmate component one vocabulary: post-run *feedback* (not a confirm
prompt), `max*Count` limits, `storage-key` for persisted state, `presentation` for the popup / sheet
choice. Values and defaults are unchanged. No aliases.

| rc02 attribute / property | rc03 |
|---|---|
| `confirmation` / `isConfirmationShown` | `show-feedback` / `isFeedbackShown` |
| `confirmation-duration` / `confirmationDuration` | `feedback-duration` / `feedbackDuration` |
| `favorites-limit` / `favoritesLimit` | `max-favorite-count` / `maxFavoriteCount` |
| `recent-limit` / `recentLimit` | `max-recent-count` / `maxRecentCount` |
| `usage-key` / `usageKey` | `storage-key` / `storageKey` (default `'web-commandpalette:usage'`) |
| `mobile-presentation` / `mobilePresentation` | `presentation` (`auto` \| `floating` \| `fullscreen`) |
| `stepOptionsCallback` | `getStepOptionsCallback` (one ctx — [below](#every-callback-takes-one-ctx)) |
| `renderConfirmationCallback` | `renderFeedbackCallback` ([below](#confirmation-is-now-feedback)) |

### UI string keys are flat elementType.name

Every `labels` key is `<elementType>.<name>` (`buttons`, `tooltips`, `ariaLabels`, `placeholders`,
`headers`, `labels`, `messages`), the key shape of every Keenmate component. A text shown in two
places now has one key per place, so a translator can word the visible heading and the screen-reader
name differently. English defaults are unchanged. `''` is now deliberately empty (the string is not
rendered; an `''` aria label removes the attribute); a missing / `undefined` key falls back to the
default. Twins share `<name>` (`labels.close` / `ariaLabels.close`, `labels.addFavorite` /
`tooltips.addFavorite` / `ariaLabels.addFavorite`), so an unset `ariaLabels.*` / `tooltips.*` key
follows a customized same-name sibling.

| rc02 key | rc03 key(s) |
|---|---|
| `placeholder` / `filterPlaceholder` | `placeholders.idle` / `placeholders.filter` |
| `emptyText` | `messages.noResults` |
| `searching` | `messages.searching` (the loader's visible text, also its name) |
| `searchingIn` / `typeToSearch` | `labels.scopeSearchingIn` / `messages.typeToSearch` |
| `commands` | `headers.commands` (home heading) + `labels.scopeCommands` (context pill) |
| `search` / `searchContexts` | `headers.search` / `labels.scopeContexts` |
| `favorites` / `recent` | `headers.favorites` / `headers.recent` + `labels.scopeFavorites` / `labels.scopeRecent` |
| `pageOf`, `navigate`, `select`, `back`, `pages`, `next`, `run`, `lastUsed` | `labels.<same name>` |
| `close` | `labels.close` (footer hint) + `ariaLabels.close` (close button) |
| `fullscreenTitle` | `headers.fullscreen` |
| `dialogLabel` | `ariaLabels.dialog` (dialog) + `ariaLabels.input` (search input) |
| `removeToken` / `resultsCount` | `ariaLabels.removeToken` / `ariaLabels.resultsCount` |
| `addFavorite` / `removeFavorite` | `labels.*` (footer hint) + `tooltips.*` (star title) + `ariaLabels.*` (star name) |
| `showAll` | `buttons.showAll` |
| `noFavorites` / `noRecent` | `messages.noFavorites` / `messages.noRecent` |
| `done` | `headers.done` (feedback heading) + `ariaLabels.done` (announcement prefix) |

The instance `labels` takes the short keys above or the full page-wide keys
(`web-command-palette.messages.noResults`); `labels` is now also a JSON attribute
([New features](#new-features--search-localization-and-icons)).

### Labels drawn as content are HTML, counts are locale-formatted

Labels resolve through core `/locale` `createLabels`, the core label standard:

- **HTML where drawn as content.** Headings, footer hints, the empty / loading / pagination text,
  `buttons.showAll` and the feedback heading `headers.done` are HTML templates (the `{…}` values stay
  escaped). Attribute, placeholder, pill, badge and announcement labels stay plain text. A label with
  a literal `<` or `&` in those places must escape it, or set
  `window.components.security = { shouldEscapeLabels: true }`.
- **Locale-formatted counts.** `{count}`, `{page}` and `{total}` (`labels.pageOf`,
  `ariaLabels.resultsCount`, `buttons.showAll`) are formatted for the resolved locale — `12 345` in
  Czech, `12,345` in English (rc02 printed `12345` everywhere). Pin the format with
  `locale="en-US"` on the element.

### Events lose the cp prefix, one action event per command run

Events follow the shared Keenmate model (core `/actions`, SPEC §12.5 / §12.12). They bubble but are
**not composed** (rc02: `composed: true`), so a listener above an enclosing shadow root no longer
hears them. The camelCase `on*` twin is called with the event **detail** (rc02: a listener receiving
the `CustomEvent`), then the DOM event fires with the same object. Every detail carries `controller`
and `element` (non-enumerable, so `JSON.stringify` / a LiveView `pushEvent` see only the data) plus
`presentation`, `isFullscreen`, `isModal`.

| rc02 | rc03 |
|---|---|
| `cp-open` / `onCpOpen(e)` | `open` / `onOpen(detail)` |
| `cp-close` / `onCpClose(e)` | `close` / `onClose(detail)` |
| `cp-select` / `onCpSelect(e)` — `{ item, scope }` | `result-select` / `onResultSelect(detail)` — `{ result, scope }` |
| `cp-command` — `{ commandId }` (instant command) | `action` / `onAction(detail)` — `{ action: 'custom', id, item, source: 'palette', selections: [], … }` |
| `cp-complete` — `{ commandId, selections }` (wizard done) | the same `action` event, after the last answer, with `selections` |
| `cp-ready` / `onCpReady(e)` | `ready` / `onReady(detail)` (core; [lifecycle](#new-features--interaction-model-and-lifecycle)) |
| `e.detail.commandId` | `e.detail.id` (and `e.detail.item` = the command) |

Running a command — Enter / click on a command without `steps`, the last wizard answer, or its
hotkey — goes through core `runAction`: `beforeActionCallback(detail)` → the command's
`onClick(detail)` → `onAction` → the `action` event. The event is dispatched a microtask later than
`cp-command` / `cp-complete` were (the before-hook may be async).

### Data fields are renamed

Commands are core action items (`Command extends ActionItem`), so they share field names with every
Keenmate toolbar and menu. `Result.title` / `subtitle`, `Selection.label` and `UsageEntry.label` are
unchanged: they are persisted verbatim in recents.

| rc02 | rc03 |
|---|---|
| `Command.shortcut` (`'/go'`, the slash token) | `Command.trigger` |
| `Command.name` | `Command.text` |
| `Command.hotkey` (`'g d'`) | `Command.shortcut` (the key chord / sequence, as on every core `ActionItem`) |
| `Context.shortcut` (`':products'`) / `Context.name` | `Context.trigger` / `Context.text` |
| `Context.search(query, signal)` | `Context.searchCallback({ scope, term, signal })` |
| `Option.label` | `Option.text` |
| `Step.freeText` / `Step.search` | `Step.isFreeTextAllowed` / `Step.isLiveSearch` |
| `Step.shouldShow(selections)` | `Step.getIsVisibleCallback({ commandId, stepId, selections })` |
| `Step.load(ctx, signal)` | `Step.getOptionsCallback({ commandId, stepId, term, selections, signal })` |

A LiveView bridge keeps `data-search-event` / `data-step-options-event`; it must listen to
`result-select` / `action` instead of `cp-select` / `cp-complete` / `cp-command`, push `term` (not
`query`), and send the new field names.

### Every callback takes one ctx

Every ctx carries `controller` and `element` (non-enumerable, like `signal`) and the presentation
flags.

| rc02 | rc03 |
|---|---|
| `searchCallback(scope, query, signal)` | `searchCallback({ scope, term, signal })` — core's shared `SearchCallbackContext` (`{ term, signal, entries }`, `entries` always `[]`) + `scope` |
| `stepOptionsCallback({ commandId, stepId, query, selections }, signal)` | `getStepOptionsCallback({ commandId, stepId, term, selections, signal })` |
| `loadUsageCallback()` | `loadUsageCallback(ctx)` |
| `saveUsageCallback(entry)` | `saveUsageCallback({ entry })` |

Destructuring `({ scope, term, signal })` works; code that typed the search ctx by hand should use the
exported `SearchContext`.

### Confirmation is now feedback

The post-run line is feedback, not a confirm prompt: `renderConfirmationCallback(ctx)` →
`renderFeedbackCallback(ctx)` (types `FeedbackContext` / `RenderFeedbackCallback`). The ctx's `type`
is `'action' | 'select'` (rc02: `'complete' | 'command' | 'select'`), `commandName` → `commandText`,
`item` → `result`. The result is read by core `renderSlot`: a string = HTML, any `Node` (rc02:
`HTMLElement` only) = mounted, `null` / `undefined` = the built-in line, `false` = no feedback.

### setCommands / setContexts are removed

`el.setCommands(list)` / `el.setContexts(list)` → assign `el.commands` / `el.contexts` (also settable on
`el.controller`). `openWith(query)`'s parameter is named `term` (no call-site change).

### Persisted favorites and recents move

Favorites / recents persist through core `createStateStore()`:

- localStorage key `<usage-key>` → `km-state:web-command-palette:<storage-key>`, value
  `{ entries: UsageEntry[] }` (rc02: the bare array). Stored favorites / recents are **not** carried
  over.
- A stored search result is `UsageEntry.result` (rc02: `item`); an entry without `result` is skipped.
  To keep them with your own `loadUsageCallback`:
  `entries.map((e) => e.item && !e.result ? { ...e, result: e.item } : e)`.
- `localStoragePersistence` is removed from the exports; `UsagePersistence` / `UsageStore` stay.

### Item icons follow core's icon rule

Item icons render through core `renderIcon` (+ `ICON_CSS`), the one icon order of every Keenmate
component:

| `icon` value | rc02 | rc03 |
|---|---|---|
| markup (`<svg …>`) | inserted raw | inserted raw (unchanged) |
| core built-in name (`search`, `check`, `settings`, `delete`, …) | `.pa-icon--<name>` (a solid square, no glyph) | masked from `--base-icon-<name>` (nothing drawn when the token is unset) |
| other one-word name (`gear`, `chevron-right`) | `.pa-icon--<name>` (a solid square without a glyph) | your `renderIconCallback` → page `window.components.renderIconCallback` → icon-font `<i class="cp__icon gear">` |
| `x` | alias of `close` | no alias |
| `fa.gear` (other characters) | stripped into a name | text |

Give a built-in name its glyph with `--base-icon-<name>` (a `:root` theme such as
`@keenmate/base-css-variables`, or on the element). The palette's own glyphs (☆ / ★, the token ✕, the feedback ✓) keep their
`--cp-icon-*` knobs. The package's `renderIcon` export is gone: import core's.

### Theming reads the base-css-variables 2.0 contract

The palette no longer compiles pure-admin-core's `_command-palette.scss`; its CSS is its own, on the
`@keenmate/base-css-variables` 2.0 names:

- `--base-primary-*` (was `--base-accent-*`), `--base-input-text-color` (was `--base-input-color`),
  `--base-on-<role>-text-color` (was `--base-text-on-<role>` / `--base-text-color-on-accent`). A 1.x
  theme no longer recolours the palette.
- `--cp-*` knobs are declared on `:host`: set them on the element (`web-command-palette { --cp-width:
  680px }`); a `--cp-*` set only on an ancestor no longer reaches the palette. `--base-*` on `:root`
  or any ancestor works as before.
- The phone sheet's ✕ is core's sheet chrome: its glyph is
  `--cp-sheet-close-icon` (rc02: `--cp-icon-close`), and new `--cp-sheet-*` knobs style the bar.

### CSS classes are BEM on the block cp

Every class in the shadow root is BEM on the block `cp`. `::part()` names (`palette`, `backdrop`,
`container`, `input`, `results`, `footer`) are unchanged.

| rc02 | rc03 |
|---|---|
| `.pa-command-palette`, `--active` / `--fullscreen` / `--sm` / `--lg` / `--xl` | `.cp`, `.cp--active` / … |
| `.pa-command-palette__<element>[--<modifier>]` | `.cp__<element>[--<modifier>]` |
| `.pa-command-palette__loader` (the "Searching…" row) | `.cp__loading`; core's spinner `.cp__loader` in `.cp__loader-slot` |
| `.cp-confirming`, `.cp-confirm`, `.cp-confirm__<x>` | `.cp--confirming`, `.cp__confirm`, `.cp__confirm-<x>` |
| `.cp-heading`, `.cp-more`, `.cp-star` / `.cp-star--on`, `.cp-item--default` | `.cp__heading`, `.cp__more`, `.cp__star` / `.cp__star--on`, `.cp__item--default` |
| `.pa-icon`, `.pa-icon--<name>` | `.cp__icon`, `.cp__icon--<name>` (core `.km-icon`) |
| `.pa-badge`, `.pa-badge--<variant>`, `.pa-badge__remove` | `.cp__badge`, `.cp__badge--<variant>`, `.cp__badge-remove` |

The host is `display: block` (rc02: `display: contents`). It holds no in-flow content (the dialog is
`position: fixed`), so it takes no space; in a flex / grid parent it is an empty item that a `gap`
counts.

### The palette is a modal, z-index modal tier

`--cp-z-index` is the modal tier, `var(--base-z-modal, 7000)` (rc02: `10500`). The palette now sits
below page dropdowns / popovers (7500 / 7600), toasts and tooltips, like every core dialog and
sheet; the page behind is `inert` while it is open. To keep the old stacking, set
`--cp-z-index: 7601` on the element.

### Keyboard shortcuts are core's

Shortcuts bind through core `/actions` (`bindShortcuts`, `matchesShortcut`, `formatShortcut`):

- Keycaps use core's platform format: `Ctrl+D` / `Ctrl+F` (rc02: `Ctrl D`; Apple `⌘D` unchanged), a
  sequence reads `G` `D` (rc02: `g` `d`), an explicit `Ctrl+K` shows `⌃` `K` on a Mac.
- Ctrl/⌘ is exact (`Mod`): an extra Shift no longer counts — Ctrl+Shift+K does not toggle.
- The sequence window is 1000 ms (rc02: 1200 ms). The first key of a sequence (`g`) has its default
  prevented while a sequence is possible. Any key sequence works for a command `shortcut` /
  `favorites-hotkey` / `recent-hotkey`, not only `g <letter>`.

### Announcements go to core's live region

The result count, the empty-state text and "Done: …" go to core `announce()`'s one page-wide live
region (`body > [data-km-announcer]`, readable while the modal makes the page inert). The palette's
own visually hidden live region is gone. The visible context pill (`.cp__context`,
`aria-live="polite"`) stays.

### The engine is CommandPaletteEngine

`PaletteMachine` → `CommandPaletteEngine`. rc02's host had one function per setting
(`commands()`, `pageSize()`, `debounceMs()`, `labels()`, `starKey()`, …); now the host keeps only the
hooks (`changed`, `effect`, `context?`, `element?`, `error?`) and every setting is a plain option with
the element's input name.

```js
// rc02
new PaletteMachine({ commands: () => list, pageSize: () => 8, debounceMs: () => 150, starKey: () => 'Ctrl+D', changed, effect });
// rc03
new CommandPaletteEngine({ changed, effect }, { commands: list, pageSize: 8, searchDebounce: 150, favoriteKey: 'd' });
```

- `starKey` (the drawn keycap text) → `favoriteKey`, the element's `favorite-key`: the key letter
  (`'d'`, `''` = off); the engine draws the keycap itself.
- `refresh()` / `displayChanged()` are removed — `engine.setOptions(partial)` applies changes.
- `Effect` `{ type: 'command' | 'complete', commandId }` → `{ type: 'action', command, selections }`;
  the `select` effect carries `result`; `effect()` may answer `false` / a Promise to veto.

## Behaviour changes

### Filtering ignores accents

The client-side filter (the `/` and `:` lists, static steps, favorites / recent lists, the commands /
contexts prepended to global search) is core's standard search: it ignores case **and diacritics** by
default — `ces` finds `Český` (rc02: a lower-cased substring match). The `<mark>` highlight follows the
same rules. To restore rc02's matching, set `search-behavior="case-insensitive"`. Provider callbacks
still get the term as typed (trimmed).

### The loader starts with the provider call

Provider calls run through core `createAsyncRunner`: same `search-debounce`, a superseded call's
signal aborts and its late answer is dropped. The loader now appears when the provider is called, not
on the keystroke — no loader during the debounce wait, and a synchronous provider (an array, not a
Promise) never shows one. The result-count announcement waits until the answer lands.

### Phone Back and the inert page

The palette is a core modal (`startModalSession`). The phone Back gesture (and the browser Back
button) acts like Esc: it steps back first (wizard step, context search, a full favorites / recent
list), then closes — rc02 left the page with the palette open. The page behind is `inert` while it
is open. Tab from a token's remove button moves to the next tabbable control in the dialog (rc02:
straight to the input). Opening a page dropdown no longer dismisses an open palette.

### The mobile breakpoint is 768px

The `mobile` width bucket ends at 768px (rc02: 640), `tablet` at 1024px (`--base-breakpoint-mobile` /
`--base-breakpoint-tablet`, or core `configureBreakpoints()`). Device class and
`presentation="auto"` are unchanged.

### An invalid size keeps the previous value

`size="huge"` warns, fires `input-rejected` and keeps the size it had (rc02: fell back to the default
size). Removing the attribute still resets it.

### Warnings reach the console by default

Core loggers default to `warn`. A second connected palette's "only the first owns the global
hotkeys" warning now prints; silence it with
`window.components['web-command-palette'].logging.setLogLevel('error')`.

### Motion follows the shared contract

Under `prefers-reduced-motion: reduce` the `--cp-transition-*` durations are `0s` (core
`MOTION_CSS`), so hover / focus transitions stop too (rc02: only the dialog animations). Closing now
animates (backdrop fade, dialog slide up), instant at `motion="none"`, an ancestor
`data-motion="none"` or OS reduced motion; `close()` still closes at once (`isOpen`, the `open`
attribute, focus return and the `close` event happen at the start). The feedback countdown bar is
left out whenever motion is off (rc02: only under reduced motion, where it stood still); the
`feedback-duration` timer keeps its time.

## New features — interaction model and lifecycle

### Commands are action items, with veto hooks

A command gains the core action-item fields: `tooltip` / `getTooltipCallback`, `cssClass` /
`getClassCallback`, `isVisible` / `getIsVisibleCallback` (hidden everywhere — lists, global search,
recents, its hotkey), `isDisabled` / `getIsDisabledCallback` (greyed, `aria-disabled`, doesn't run),
`isDanger` (danger title color), `getTextCallback`, `getIconCallback` and `onClick(detail)`.

`beforeActionCallback(detail)` → `false` cancels a command run (async OK: no `onClick`, no event,
nothing recorded; a wizard steps back to its last answer). `beforeResultSelectCallback({ result, scope })`
→ `false` cancels a result selection.

```js
palette.beforeActionCallback = async (d) => d.id !== 'delete-all' || (await askServer(d.id)); // false = cancel
```

### el.controller

`el.controller` (`CommandPaletteController`, a frozen core facade) is the public surface every ctx and
event detail carries: `open`, `close`, `toggle`, `reset`, `openWith(term)`, `openFavorites`,
`openRecent`, read-only `isOpen`, settable `commands` / `contexts`.

### Lifecycle from core

`ready` fires once, on the microtask after the first build; `el.isReady`, the `ready` attribute,
`:state(ready)` and `await el.whenReady()` flip at the same moment. Hold the first build with the
`defer` attribute (`shouldDefer`) and call `el.release()` once listeners / config are set.
`el.destroy()` tears the element down for good.

## New features — search, localization and icons

### search-behavior and search-match

`search-behavior` (`normalized` | `case-insensitive` | `exact`, default `normalized`) and
`search-match` (`contains` | `equals` | `starts-with` | `word-starts-with` | `ends-with` |
`word-ends-with` | `regex`, default `contains`) — the same names, values and defaults as
web-multiselect. Changing either re-runs the current search.

### Page-wide labels, translateCallback and locale

- **Page-wide dictionary:** `window.components.locale.labels` — one flat dictionary of full keys,
  `{ 'web-command-palette.messages.noResults': 'Nic nenalezeno' }`. Instance `labels` win.
  Assigning `window.components.locale` re-renders an open palette in place (mode, query and wizard
  answers kept).
- **`translateCallback({ component, key, template, params, locale })`** on the element — asked for
  every key the instance `labels` did not set, before the page-wide
  `window.components.locale.translateCallback` (i18next / ICU); `null` / `undefined` = not mine.
- **`locale`** (attribute + property): BCP-47 locale for the label numbers and `ctx.locale`; unset =
  the page-wide locale, else the browser.
- **`labels` is also a JSON attribute:** `labels='{"placeholders.idle":"Hledat…"}'`; malformed JSON
  warns and keeps the previous value.

```html
<web-command-palette locale="cs" labels='{"messages.noResults":"Nic nenalezeno"}'></web-command-palette>
```

### renderIconCallback and the page-wide icon hook

`el.renderIconCallback(name, ctx)` (`ctx = { component, element, prefix: 'cp', item, kind }`) maps an
icon name to markup for this palette, asked after a built-in name and before the page-wide
`window.components.renderIconCallback`; `null` / `undefined` = not mine, `''` = no icon. Assigning the
page-wide hook after the palette rendered repaints the item icons in place (query, active row and
scroll kept).

```js
palette.renderIconCallback = (name) => name === 'gear' ? '<svg …></svg>' : null;
```

## New features — presentation, styling and state

### presentation and responsive rules

`presentation` (`auto` | `floating` | `fullscreen`) plus core responsive rules: partial configs per
device class (`{ device: { mobile: … } }`) and / or window-width bucket (`{ breakpoint: … }`),
page-wide (`window.components.responsive`), per tag (`window.components['web-command-palette'].responsive`)
or per instance (`el.responsive` / JSON attribute `responsive`, `el.responsiveCallback`).

### Custom CSS in the shadow root

`custom-styles` (`customStyles`) and `getCustomStylesCallback(ctx)`, after the page-wide layer
`window.components['web-command-palette'].customStyles` / `.getCustomStylesCallback`. An `@import` is
also linked once in the document head, so imported fonts work.

### Custom loader

`renderLoadingCallback(ctx)` (`ctx = { component, context, containerElement, element, label }`,
optional cleanup return) draws the searching loader; it beats the page-wide
`window.components.renderLoadingCallback`. The default is core's loader, themed with `--cp-loader-icon`
/ `-rotate` / `-duration` / `-size` / `-color`.

### Favorites and recents in your own store

`loadStateCallback` / `saveStateCallback` (core `LoadStateCallback` / `SaveStateCallback<PaletteUsageState>`)
let the page keep the whole list (`{ key, state: { entries } }` on every save). Set both; either one
switches localStorage off. `loadUsageCallback` / `saveUsageCallback` (one entry per call) stay and win
when set.

### Motion level

Core's `motion` attribute (`auto` | `none` | `snappy` | `smooth`) and the page-wide
`window.components.motion` set the palette's speed; `motion="none"` makes open / close instant.

### Typed properties

`CommandPaletteConfig` lists exactly the input rows and is merged into `CommandPaletteElement`, so
`el.presentation = 'sideways'` or `el.notAnInput` is a type error.

## New features — building your own UI

`CommandPaletteEngine` is the public, DOM-free engine: `new CommandPaletteEngine(host, options)`,
`engine.setOptions(partial)` (merges and re-applies what it names; `undefined` = back to the default;
an unknown key warns once and is skipped) and `engine.getOptions()`. Options carry the element's input
names and defaults (`commands`, `contexts`, `searchCallback`, `getStepOptionsCallback`, `display`,
`pageSize`, `searchDebounce`, `searchBehavior`, `searchMatch`, `labels`, `translateCallback`, `locale`,
`usage`, `maxRecentCount`, `maxFavoriteCount`, `favoriteKey`). `engine.labels` is the resolved label
API, `engine.isPending` says a debounce or answer is outstanding. See
[docs/usage.md → Build your own UI](https://github.com/Keenmate/web-commandpalette/blob/prod/docs/usage.md#build-your-own-ui).

## Visible changes without a migration

- **Rows use the shared item states:** the active row is the focused state — an inset
  `--base-focused-outline`, no fill (rc02: a 10% primary fill); hover is `--base-hover-bg`. Set
  `--cp-item-active-bg` for a fill.
- **The search input is a control:** `--base-input-border` outline, focus border + halo, no vertical
  padding (taller theme fonts no longer clip).
- **Standalone colors follow the contract:** accent `#3b82f6` (rc02: sky `#0ea5e9`); text on fills is
  black or white by APCA contrast; disabled rows dim with `--cp-disabled-opacity` (`0.65`); the query highlight follows
  the primary color.
- **Standalone dark mode** from the page signal (`.dark`, `[data-theme]`, `[data-bs-theme]`, a
  `theme-source` element) via core's theme context — works in every engine (rc02: `:host-context()`,
  Chromium only).
- **Phone sheet bar** is core's sheet chrome: a round, borderless 44px ✕ chip (rc02: a bordered
  input-height square).
- **UMD bundle** about 10 kB smaller (unused pure-admin rules no longer shipped).

## Fixes

- A title with `İ` (or another character whose lower case is longer) before the match highlighted the
  wrong characters.
- Firefox routed one edit twice (the search restarted, a custom loader ran twice).
- The phone sheet keeps rows and search clear of the landscape nav bar / camera cutout; a scroll at the
  end of the results no longer chains to the page; the caps use `dvw` / `dvh`.
- `display="tokens"`: an answer containing `$&`, `$'` or `$$` garbled its badge's "Remove …" label.
- The narrow-window `max-height: 60vh` results cap applies again.
- `page-size` changed while the palette is open re-pages the current results at once (rc02: from the
  next keystroke).
- The star button sets no empty `aria-label` / `title` when its label is `''`.
