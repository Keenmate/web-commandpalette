Every UI string goes through core /locale. Keys are flat <elementType>.<name> (placeholders.idle, labels.navigate, messages.noResults, ariaLabels.close, …) — the full list is DEFAULT_LABELS / the labels property in docs/usage.md. Per key: the instance labels (short or full web-command-palette. key) → the element's own translateCallback → the page-wide translateCallback → the page dictionary window.components.locale.labels → the built-in English. The palette is a modal, so each readout box opens its palette for a moment, reads the strings from the shadow root and closes it again — use the Open buttons to look yourself. The page-wide toggles (LO02, LO03, LO05, LO06) are page-wide: they change every palette on this page, on purpose.

LO01 · Instance labels

Override texts on ONE palette with the labels property. A short key (placeholders.idle, labels.navigate) and a full key (web-command-palette.labels.select) both work; every key you leave out stays English (the Esc hint still reads Close). The neighbour palette is untouched.

rendered strings (command list)

    
el.labels = {
  'placeholders.idle': 'Napište / pro příkazy…',          // short key
  'labels.navigate': 'Pohyb',
  'web-command-palette.labels.select': 'Vybrat',         // full key
};   // a property only — labels has no attribute









    
LO02 · Page-wide dictionary

    

        One flat dictionary on window.components.locale.labels — the app's translation JSON as loaded, full keys
        'web-command-palette.<elementType>.<name>', other components' keys side by side — translates every
        palette on the page at once. Assigning window.components.locale re-renders an open palette in place (mode,
        query and wizard answers kept). Keys an instance set itself (LO01) still win.
    

    

        
        
        
    

    
rendered strings

    
// e.g. const labels = await (await fetch('/i18n/cs.json')).json();
window.components.locale = {
  labels: {
    'web-command-palette.placeholders.idle': 'Napište / pro příkazy, : pro hledání…',
    'web-command-palette.labels.navigate': 'Pohyb',
    'web-command-palette.labels.select': 'Vybrat',
    'web-command-palette.labels.close': 'Zavřít',
    'web-command-palette.messages.noResults': 'Nic nenalezeno',
    'web-multiselect.placeholders.search': 'Hledat…',      // other components share the same JSON
  },
};









    
LO03 · translateCallback

    

        An app with its own i18n (i18next, FormatJS, …) answers keys through a callback instead of a dictionary. It gets
        { component, key, template, params, locale } — key is the full
        web-command-palette.<elementType>.<name> — and returns the text, or null = not mine.
        The element's own translateCallback is asked first (German, only labels.select here); its
        null passes the key on to the page-wide one (a small Slovak i18next-like lookup). A key the instance
        labels set (the second palette's labels.select) is never sent to any callback.
    

    

        
        
        
        
    

    
rendered strings

    
// an i18next-like lookup: a dictionary + t(key, params)
const sk = { 'web-command-palette.labels.select': 'Vybrať', 'web-command-palette.labels.navigate': 'Pohyb', … };
const t = (key, params) => sk[key]?.replace(/\{\{(\w+)\}\}/g, (_, p) => params?.[p] ?? '');

// page-wide — every component on the page
window.components.locale = { translateCallback: ({ key, params }) => (key in sk ? t(key, params) : null) };

// one element — asked BEFORE the page-wide callback; null = not mine
el.translateCallback = ({ key }) => (key === 'web-command-palette.labels.select' ? 'Auswählen' : null);

// instance labels are never sent to a callback
other.labels = { 'labels.select': 'Instance wins' };









    
LO04 · Screen-reader name / tooltip follow

    

        An ariaLabels.x / tooltips.x nobody set takes the first customized key of the same
        <name>, so translating one visible caption translates its twins. Translate only the footer hints
        labels.addFavorite and labels.close: the row's star button follows — its tooltip
        (tooltips.addFavorite) and accessible name (ariaLabels.addFavorite) — and so does the
        sheet's close button (ariaLabels.close). The box reads title / aria-label from the
        shadow root.
    

    

        
        
    

    
star button + close button

    
el.labels = { 'labels.addFavorite': 'Přidat do oblíbených', 'labels.close': 'Zavřít' };
// → star title "Přidat do oblíbených (Ctrl+D)" AND aria-label "Přidat do oblíbených"
//   close button aria-label "Zavřít" (ariaLabels.close was never set)
// an explicitly set tooltips.x / ariaLabels.x always wins over the twin









    
LO05 · locale + formatting

    

        Numbers in labels ({page} / {total} / {count} in labels.pageOf,
        ariaLabels.resultsCount, buttons.showAll) are formatted for the palette's
        locale → window.components.locale.locale → the browser. The element's own
        locale wins over the page locale; unset (or auto) follows it. The palette formats no
        dates — numbers only. The Numbers context below returns 12,345 rows.

LO06 · shouldEscapeLabels

    

        Content labels (headings, hints, empty / loading / page texts) are HTML templates: the template's own
        <b> renders bold, while a {name} value — here the context's text
        <i>Ann</i>, DATA from the app — is always escaped, so its tags show as text instead of turning
        italic. With window.components.security.shouldEscapeLabels the whole label is text: the template's
        <b> shows as characters too (for apps whose translators must not inject markup).
    

    

        
        
    

    
the empty-state row: markup → shown text

    
el.contexts = [{ id: 'ann', trigger: ':ann', text: '<i>Ann</i>' }];
el.labels = { 'messages.typeToSearch': 'Type to search <b>{name}</b>' };
// → Type to search <b>&lt;i&gt;Ann&lt;/i&gt;</b>   (bold, tags of the data as text)
window.components.security = { shouldEscapeLabels: true };
// → Type to search &lt;b&gt;&lt;i&gt;Ann…   (the whole label is text)
